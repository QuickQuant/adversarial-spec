What It Is

Claude Code skill multi-model debate Fizzy board coordination

adversarial-spec is a Claude Code skill for refining specs through multiple language models. It takes a product spec, sends it to critics, reconciles their objections, and moves the work through the project pipeline until the spec is ready for execution and implementation.

How It Works

debate vs gauntletsingle command-line invocation

📣 Debatecollaborative Opponents

Debate uses collaborating critic models, called Opponents, to improve a draft over numbered rounds. The goal is convergence: objections are answered, accepted, or turned into revisions.

draftopponent critiquereconcileround checkpointconvergence check
⚠ changing during post-fable-hardening-skill, in progress

⚔ Gauntlethostile Adversary personas

Gauntlet is a later stress test. Named Adversaries attack the spec, evaluators sort the attacks, and the output is Concerns: specific risks that must be accepted, dismissed, acknowledged, or deferred.

1 attack2 synthesize3 filter3.5 cluster4 evaluate5 rebut6 adjudicate7 final boss

Model Calls

The models layer routes API-backed calls through LiteLLM and subscription models through command-line subprocesses. A preflight ping catches bad model names and broken auth before long critique runs.

Checkpointing

Debate sessions and gauntlet phases write restartable checkpoints. Gauntlet checkpoints use FileLock-guarded integrity envelopes, so resume can reject mismatched or corrupted state.

Gate Enforcement

The command line enforces pipeline-card and test-staleness gates before dispatch. The current hardening spec is expanding this pattern so fewer gates depend on conductor memory.

Top Concerns

from 2026-06-11 architecture rollupfix-first summary

CON-001 One model-call wrapper

Three LiteLLM call paths carry different defaults. A single low-level wrapper would remove silent drift.

CON-002 Token tracking still leaks upward

The extraction landed, but gauntlet phases still import the global tracker. Model dispatch should own accounting.

CON-009 Prompt module shadowing

prompts.py name collision can load the wrong module in standalone paths; packaging or renaming should remove the trap.

CON-003 Oversized gauntlet orchestrator

run_gauntlet() mixes phase flow, checkpoints, manifests, medals, and stats. A phase table would narrow blast radius.

CON-007 Divergent command surfaces

debate.py and gauntlet/cli.py expose different flag names and timeout defaults for the same backend.

CON-008 Dispatch race

Same-role workers share a baseline file and can miss conductor updates. Baselines need per-worker or per-Codex-session identity.

CON-004 Remaining dead code

Most deleted shims are gone, but a focused cleanup should remove the remaining deprecated commands and stale remnants.

CON-005 Inline late-phase prompts

Gauntlet phases 5 and 7 still carry inline prompt text instead of centralizing it with the gauntlet prompt templates.

CON-006 sys.path packaging debt

Several scripts patch import paths directly. Proper package config and relative imports would remove fragile startup behavior.
