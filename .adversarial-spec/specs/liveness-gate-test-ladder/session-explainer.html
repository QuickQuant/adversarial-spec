The problem this kills

A critical seam can have rich prose, a clean design, and a wall of green unit tests — and still have never actually run. The tests mock the seam away. "Liveness" is the evidence that the real path executed.

🎭 Mock theatre (rejected)

  • Behaviour is mocked; the seam is never exercised.
  • "Unit-green" is counted as proof the path works.
  • A MOCK is justified with a scale / cost / time excuse.
  • Owner-written "pass/fail" prose is trusted at face value.

✅ Liveness (required)

  • Real data, or a named live / fault-induced technique, runs the seam.
  • A typed run_evidence receipt is captured by the skill-runner.
  • A MOCK is only valid if no technique could induce it — cited in technical_constraint.
  • The skill never trusts owner-reported results — it re-runs and records its own.
