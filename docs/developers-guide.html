The vertex, live 04 · MISSION CONTROL

Agents on the board

Eight cards, two unlock waves. A card shows its family color — orange or teal — once every card it depends on is done; until then it stays grey with a stack of locks, one per level of chain still above it. A colored lock means that blocker is in progress right now; deeper levels stay grey. And no agent ever reviews or tests its own card — work moves right only by passing to a different pair of hands.

Lane priority & claims

A worker never asks "what next?" — pipeline_do_next_task answers it deterministically. It walks lanes in a fixed priority and, within New Todo, dispatches critical-path-first:

# TASK_PRIORITY — fix before you build
Failed Review  → fix      # reviews block new work
Review         → review
Untested       → test
New Todo       → implement  # cp_priority orders the ready set
Passed Test    → sweep

A claim is not a lane — it stamps claim_status, claim_agent, claim_ts on the card and is made authoritative by optimistic locking. Abandoned claims expire after CLAIM_TTL_SECONDS (default 3600).

The schedule is immutable

_build_schedule runs once at load_plan and is frozen on the session card. It is a pure function — no I/O — so the same plan always yields the same waves.

def _build_schedule(tasks):
    topo  = kahn_topological_sort(tasks)   # ties by task_id
    waves = ready_levels(topo)             # parallel-safe sets
    cp    = longest_weighted_path(topo)    # S:1 M:2 L:3 XL:4
    return Schedule(order=waves, critical_path=cp,
                    parallel_capacity=len(ready_now))

A depends_on pointing at a non-leaf container is rewritten to its leaf descendants at load; a third pass over the expanded graph raises CROSS_GRAPH_CYCLE for loops that only appear after expansion.

run_gauntlet() drives seven phases. Adversary × model pairs attack in parallel; surviving concerns are clustered deterministically, evaluated by frontier models, rebutted, and adjudicated with medals. Every phase checkpoints to an integrity-hashed envelope.

fizzy-pipeline-mcp · the spine 06 · THE ASCENDING ARM

Verifying back
up the V

The right arm is not advisory. Each level has a mark_*_verification_complete tool, a ledger, and a closure rule: a node is verified only when its own flags are set and every child beneath it is already verified. You cannot certify a subsystem on top of an unverified component.

The closure recursion · _check_vv_closure_sync
def node_is_v_complete(node):
    if not all(node.flags[k] for k in
           ALTITUDE_OBLIGATIONS[node.altitude]):
        return False          # own kinds unmet
    for child in node.children:
        if not node_is_v_complete(child):
            return False      # gate: unverified_descendant
    if node.altitude == "system" and v >= 5:
        return node.flags["system_validation"]
    return True

The first incomplete descendant is surfaced by id — there is no "mostly verified." Subsystem marks additionally require ≥2 crosses (distinct components that integrate).

Quorum scales with blast radius

Altitude is blast radius — how far a mistake propagates — not complexity. Review rigor scales with it, and the floor is never zero (the import-time assert crashes startup if any obligation set is emptied).

The dashed line is a hash

Traceability isn't a comment — it's enforced. At load, every left-arm definition_artifact and every plan plan_artifact is re-hashed from the real file ("derive truth, don't trust the emit-time hash"). A missing artifact fails the entire load closed; nothing half-materializes.

# at load — _derive_v4_node_lift
binding.definition_hash = sha256(read(definition_artifact))
if artifact_missing:
    raise BINDING_ARTIFACT_NOT_FOUND   # 0 cards created

# at discharge — _vv_check_freshness
if sha256(read(artifact)) != bound_hash:
    raise STALE_VV   # spec drifted; re-bind to proceed

Change a left-arm spec after binding and STALE_VV fires on its right-arm gate until you re-bind. That is the V's traceability arrow, made mechanical.

The data model

UUID primary keys (UUIDv7), every row tenant-scoped by account_id. The pipeline rides on two structures:

# card_links — the typed join (the V's edges)
LINK_TYPES = ["decomposes_into",   # altitude tree
              "verifies_at_level"]  # horizontal V&V
unique(from_card, to_card, link_type)  · account-scoped

# pipeline_metadata — JSON column, default {}
{ card_type, session_id, task_id,        # → indexed virtual cols
  altitude, depends_on, schedule,
  verification_binding, *_complete }
metadata_version: bigint   # optimistic-lock counter

Four hot keys (card_type, session_id, parent_session_id, task_id) are extracted to generated, indexed columns — fast lane queries without parsing JSON.

Auth is a triad

No global board lock. Every tool call targets a board through three independent facts — and a write token can't be a read token in disguise.

# the request that creates a card
POST {base_url}/{account_slug}/boards/{board_id}/cards.json
Authorization: Bearer {api_token}

  account_slug  → selects the tenant   (URL path)
  api_token     → proves identity     (Bearer)
  board_id      → per-call parameter  (never default)

Metadata writes carry If-Match-Metadata-Version; a mismatch returns 409 METADATA_VERSION_CONFLICT with {expected, actual}. That is how parallel agents never clobber each other.

The plan seam

PLAN_SCHEMA_VERSION = 3 in the emitter must match the spine's expectation. self_check_plan() runs the validator's logic offline, so a bad tree fails in adversarial-spec before it ever reaches pipeline_load. Two repos, one definition of "legal."

The coordination plane

No orchestrator daemon. PreToolUse / PostToolUse hooks inject system messages: dispatch_check surfaces pending work, pipeline_continue forbids stopping mid-flow, pipeline_idle_retry backs off with overnight schedules. Workers can't drift.

The human gate

relay.py is a standalone Telegram daemon — the only place a person touches the pipeline. /approve and /reject patch the session's gate metadata for g1/g2/g3 and the system-verification signature. Crash-safe: offset advances before handling.
